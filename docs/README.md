# Document sets

Document sets that serve every area: how an agent finds the skill for a job (`pack/`), what the skills of one tool family share (the browser, card news, Higgsfield, Instagram, the Meta Ad Library, variations), whichever areas they are in, and what every text a skill writes shares (`writing/`). Directories of Markdown with no `SKILL.md`: this directory is declared in the repository manifest (`SKILLCDN.md`, `documents: [docs]`), so SkillCDN lists and searches everything here with `browse_repo` and `search_repo` and serves it with `read_repo_file`, without any skill. A document set that serves one area lives in that area's `docs/` instead, discovered by default next to the area's manifest. What the skills of one tool family share, whichever areas they are in, lives here as `<family>/`.

| Document set | What it is |
|---|---|
| [`higgsfield/`](higgsfield/) | What the skills that drive Higgsfield share: the sandbox, models and credits, portraits and first frames, decoding a take, and the sounds of each language, as real runs showed it. One file per topic, organized by what holds now; the skills link each from the phase that reads it. |
| [`pack/`](pack/) | How an agent finds its way in this pack: the layout, the three ways to find a skill, how a result is read, what to do when no skill fits; and the jobs index, one section per job in the words a user says, with the skill's path. Searched first. |
| [`variation/`](variation/) | What the skills that make variations share: the effect brief, the axes with a near and a far candidate, the AI feel's signals and tests, the comparison sheet, the handoff. Method only; the variation skills include four pages, the producing skills link the AI-feel page. |
| [`browser/`](browser/) | What the skills that read a website or render a page with a browser share, whichever area they are in: a browser the agent drives and how hosts differ, a headless Chromium-family browser from a shell, reading a page in full and taking its images, what stops a reading and the ways around a wall of the host, rendering an HTML page the agent wrote to PNG or PDF, frames of a public clip, a clip cut from a video and composed into a rendered slide. One file per topic; each skill includes the page every run needs and links the rest from the phase that reads it. |
| [`writing/`](writing/) | What every text shares, whichever skill writes it: the reader, the language and the register; sentences, titles and what is cut; facts, figures, hedges and quotes; what stays inside the organization; the house style of characters that stay out of its documents. One file per topic, generalized from the skills that write; each medium's sharper list stays in its skill. The news script skill of the writing area links its pages from the phase that writes, as the skills of the other areas do. |
| [`instagram/`](instagram/) | What the skills that read Instagram share: what a visitor without an account sees and the routes a browser takes to it, the sign-in prompt, the viewport, the documented sizes, a post page's data, stepping a carousel, reading a slide, the caption. One file per topic; the format study includes both pages, and a skill that posts to an account will read them too. |
| [`card-news/`](card-news/) | What the card news skills of design, product and marketing share: the routes to a format spec in their order and the fields of the spec, measured by the format study or designed by the design variations and built from by the build; the fields of the topic brief, written by the research and read by the build, with its images and video clips; the record an account that keeps posting holds (its policy, each post's state, the ledger of covered topics); and what every card news skill does the same way. A skill includes the page every run of it reads and links the rest. |
| [`meta-ad-library/`](meta-ad-library/) | What the two skills that read the Meta Ad Library share, in marketing and product: what the library is evidence of, the routes into it and their code, the URL parameters, the record a result yields, counting by age, manners and limits. One file per topic; each skill includes `ad-library.md` and links the rest from the phase that reads it. |

Handbooks and playbooks an area's people work from, written so that an agent finds and reads them without a skill, will join them.

Every document carries a front-matter `title` and `description`, or starts with a level-one heading followed by one summary paragraph, because that is what search shows, and headings that name its parts, because a search result names the sections that matched and `browse_repo` outlines a file by them. Links stay within what an agent can reach through the mount: skills, manifests, document directories, and the README of a served folder.
