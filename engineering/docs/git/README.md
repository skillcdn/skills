# Git: what every repository of this pack shares

The skills that set up or build a repository (`git-repo-setup`, and `cloudflare-new-app` and `git-studio-setup`, which run it for an app's repository and for a studio) give every repository the same layout, the same working agreement, the same test structure and the same binding to a console, so that a person or an agent who has worked in one finds everything in the next. That shape lives here once, one file per topic; each skill reads a page before the phase that needs it, and carries its own method (what it asks, where it stops, what it accepts, its rules) itself.

| Document | Holds | Read |
|---|---|---|
| [`layout.md`](layout.md) | The tree, who reads each file and when, the languages (English for everything agents read, the readers' language for the README), what the pack's other skills add later, what stays out. | When a repository is set up, and before a skill adds a file to one; read by the setup skill before its plan. |
| [`agreement.md`](agreement.md) | `AGENTS.md` section by section, `CLAUDE.md` as its import, the workflow with the binding sentence, the skills section (the project's pack read through the console, and a host's own connection on request). | When an agreement is written or a section of it changes; read by the setup skill before its files phase, linked from the new-app skill. |
| [`console.md`](console.md) | The repository's console project: which console and project, who may do what, the project's pack, the people, the binding of every checkout, the project's rules, the first goal and tasks, what lives on the board and what in the repository, the route without a console and binding later. | When a repository is set up or bound to a console; read by the setup skill before its plan. |
| [`readme-guide.md`](readme-guide.md) | The README: what it holds in which order, a template, how to make it good to look at, how it stays true. | When a README is written; read by the setup skill before its files phase. |
| [`testing.md`](testing.md) | The test structure: one check, three layers with a place and a name each, the defaults by stack, continuous integration. | When the check or the first test is written; read by the setup skill before its plan. |
| [`studio.md`](studio.md) | What a repository that keeps producing adds: the unit, something made or a round of ongoing work, with its states and the ones only a person gives, `studio.json`, the record, the ledger, the review screen, the commands, the check, how several people and agents work in it at once, the starting values by kind. | When a studio is set up, and before a skill adds a kind of file to one; read by the studio skill before its plan. |
| [`studio-know-how.md`](studio-know-how.md) | A studio's own small pack: its manifest, a skill per job that extends a skill of the pack, the policy and the pages by topic, what an agent reads at a session's start, for one job and never, how a run's findings are folded back, how a new technique is tried and adopted, serving and the checks. | When a studio is set up, when a studio skill or a page of its `docs/` is written, and at the end of a run that learned something; read by the studio skill before its plan. |

## Who reads this

[`git-repo-setup`](../../skills/git-repo-setup/SKILL.md), [`cloudflare-new-app`](../../skills/cloudflare-new-app/SKILL.md) and [`git-studio-setup`](../../skills/git-studio-setup/SKILL.md), all in this area; an agent at work in a studio reads `studio-know-how.md` by the path the studio's agreement names. None includes a page: each is read before the phase that needs it, so that the skill, with the pack's rules before it, stays within what a command prints whole. A page is at `engineering/docs/git/<topic>.md`: through a console `console skill --file <path>`, through a connection of the host's `read_repo_file`, or the file at `docs/git/` of the engineering plugin. A skill of another area that writes into a repository reads layout.md before it adds a file.
