<p align="center">
  <a href="https://skillcdn.ai/gh/skillcdn/skills/engineering"><img alt="SkillCDN: skillcdn.ai/gh/skillcdn/skills/engineering" src="https://skillcdn.ai/badge/gh/skillcdn/skills/engineering"></a>

Skills for software development and for the tooling an agent works with: writing and changing code, keeping a codebase's documents true to it, building apps and taking them to live money (payments, ads, the operator's dashboard), testing, debugging, making skills from work done, turning a body of documents into a pack an agent searches and reads through SkillCDN, and answering from such a pack with every citation checked. The area manifest next to this file ([SKILLCDN.md](SKILLCDN.md)) says who these skills are for and adds the rules every engineering skill follows on top of the repository's. The area mounts alone at `skillcdn.ai/gh/skillcdn/skills/engineering` and installs as the `engineering` plugin of the repository's Claude Code marketplace.

| Skill | Tool family | What it does |
|---|---|---|
| [`skills/skillcdn-skill-authoring/`](skills/skillcdn-skill-authoring/) | SkillCDN | A skill in this repository, or in a fork of it, from work a person and an agent have already done. Read the session first, then earlier transcripts, memory and results where the user points; keep the method and leave the product and the people out; design what is asked, what is derived, where the user is consulted and what makes a result accepted; write the skill in this layout with discovery in place of values; validate it; have a fresh agent follow the files alone; ship it with its catalog rows. Also folds a run's findings back into an existing skill. |
| [`skills/skillcdn-skill-verification/`](skills/skillcdn-skill-verification/) | SkillCDN | A skill of this repository, or of a fork of it, verified the way a user's agent will meet it. A fresh agent dry-reads its files for every place it would have to guess; a fresh agent runs the served skill through SkillCDN with its checkpoints answered as the user would; each finding is folded into the sentence it bears on, checked, and pushed on the user's word. Works on what is served, on a local change before it is pushed, and after a tool, a model or a shared page changed under the skill. |
| [`skills/skillcdn-document-pack/`](skills/skillcdn-document-pack/) | SkillCDN | Documents a person has (PDF, Word, slides, spreadsheets, HTML, exports, text) turned into a pack of documents in the SkillCDN Format, in a repository they own. Surveys the sources, plans the layout with the user, converts each with the tools the agent has, lays them out one file per document or chapter with a title and a description, writes the map of every document set, describes figures and transcribes scans as text beside the images, declares the document roots and the language in the manifest, checks the pack with the indexer's own check and commits it. |
| [`skills/skillcdn-document-research/`](skills/skillcdn-document-research/) | SkillCDN | A question answered, a reference compiled or a claim checked from a large pack of documents through SkillCDN: the maps read first, the search in the pack's own words and language, the sections a result names read by their offset and limit, a long document walked by its outline, every finding quoted with its path and heading, what the pack does not say said plainly, and the answer kept as a research note committed to the pack when the user owns it. |
| [`skills/skillcdn-doc-qa/`](skills/skillcdn-doc-qa/) | SkillCDN | A question answered now from a pack of documents through SkillCDN, with every citation checked before the answer is sent: the question framed in the pack's words, the maps read, the search by words and by meaning where the deployment does, the sections a result names read by their offset and limit, the answer drafted, every cited section read once more so that each quote is found word for word or dropped, and the answer sent with the path, the heading and the offset of each citation and what the pack does not say. Writes nothing into the pack; a note kept for the next time is the research skill's. |
| [`skills/cloudflare-new-app/`](skills/cloudflare-new-app/) | Cloudflare | A new web app from an idea, built and put live. Asks a few plain questions anyone can answer (what it does and for whom, which languages, sign-in or not, a domain or not, the look), plans it, proposes a look, builds a TypeScript app on the path Cloudflare's framework guide recommends that day (Next.js by default), mobile-first, every language in from the first commit, ready for search and AI engines, with a share image and favicon set from its brand, sign-in, a database, analytics, tests and one check; writes the working agreement a team of developers, planners and designers keeps working under; hands over to the deploy skill for the launch. |
| [`skills/cloudflare-deploy/`](skills/cloudflare-deploy/) | Cloudflare | A web project live on Cloudflare Workers, deploying itself from then on. Gets access with the user's API token (the exact steps of the day), creates the database, bucket and namespace the code binds, applies the schema, sets the secrets (generated signing keys, provider keys the user supplies), deploys, attaches the domain (owned, bought through the Registrar API with the price confirmed, or a free workers.dev address), connects the repository so that every push to main deploys and every branch previews, turns on logs and analytics, and writes `DEPLOY.md` into the project. |
| [`skills/stripe-payments/`](skills/stripe-payments/) | Stripe | Payments on a web project with Stripe, from a sandbox to live money. Asks what is sold, at what price and who the seller of record is; builds the order ledger, the hosted Checkout, the return and the webhook that settle an order exactly once, with refunds, disputes and subscriptions; registers the products, prices and webhook endpoint through the API; proves the flow in a sandbox with the Stripe CLI and a test card; switches to the live key and endpoint and lists the dashboard-only items for the owner; writes `docs/payments.md` with the operator panel's spec. |
| [`skills/meta-ads-setup/`](skills/meta-ads-setup/) | Meta Marketing API | Meta ads for a web project, from the pixel to running campaigns. Wires the measurement (a dataset per market, the pixel on public pages only, the Conversions API with deduplication, attribution from the first click to the order, privacy signals honored), creates the datasets and the domain's verification with the business's system user token, maps the ad accounts and syncs spend, builds campaigns from finished creatives the way a working account runs them, created paused and turned on only after the budget is confirmed, and writes the monitoring and optimization rules the operator panel applies. |
| [`skills/cloudflare-admin-dashboard/`](skills/cloudflare-admin-dashboard/) | Cloudflare | The operator's dashboard as a separate Worker only the operator can open: bound to the project's database, behind Cloudflare Access with a one-time email code and verified again inside the Worker so that it fails closed until protected, with its own least-privilege keys, an audit log, confirmations for anything that moves money or ads, and a cron for syncs and a daily digest; the overview, the funnel, orders and refunds, campaigns with their controls and the rules' recommendations, costs, and the system's health. |

Documents for this area are in [`docs/`](docs/README.md) next to this file, where SkillCDN discovers them by default: [`docs/skillcdn/`](docs/skillcdn/README.md) holds what the SkillCDN skills share, [`docs/cloudflare/`](docs/cloudflare/README.md) what the Cloudflare skills share, [`docs/stripe/`](docs/stripe/README.md) what the skills that take payments share, and [`docs/meta-marketing-api/`](docs/meta-marketing-api/README.md) what the skills that run Meta ads share.

How to write a skill: [guide/skill-authoring.md](../guide/skill-authoring.md). How to add one here: [guide/adding.md](../guide/adding.md), or the authoring skill above, which does those steps from the work already done; the verification skill tries a skill again from a fresh session after it changed. The `node scripts/check.mjs` check fails when a skill directory is missing from this table.
