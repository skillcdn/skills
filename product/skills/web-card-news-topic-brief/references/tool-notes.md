# Tool notes: how the tools behaved

What runs of this skill met in a search tool, a page reader and a shell, by topic, with the month where a fact can go stale, and what a run does at a site this host cannot read. What holds for any page reader, download or clip is in the pack's [reading-pages.md](/docs/browser/reading-pages.md), [video-frames.md](/docs/browser/video-frames.md) and [video-clips.md](/docs/browser/video-clips.md); this page holds what this skill's own phases met.

## Search

A thorough mode, where the tool offers one, found the week's domestic stories that the quick mode missed; use it for the first pass of each category (checked 2026-10). A run on a Korean domestic category found few of the week's stories through the search tool even in its thorough mode, and the week came instead from a portal's news search page, filtered to the past seven days and sorted by date, read with a plain request page by page (Daum's, checked 2026-10), while another portal's search page refused the fetch tool (Naver's, checked 2026-10); the portal's own article pages read fine with the fetch tool. A portal's news search page can answer a plain request with a CAPTCHA page instead (seen 2026-10): a news aggregator's RSS feed of the query, with its period parameter for the window and the market's language and region parameters, returned the stories with their dates and outlets, each link a redirect that only a browser resolves, at several seconds a link, so resolve the links of the cards kept and not of every result (Google News, checked 2026-11). A search tool's index can lag a day behind the news: a same-day story is looked for on the outlets' own pages. A photo query ("photos of <event>") returned little; the photographs came from reading the articles already found. A search for the platform's documented post size did not surface the platform's own help page (checked 2026-10); the size then comes from a guide that cites it, and the brief records which source gave it.

## A site this host cannot read

A page reader's error is not yet a refusal: the page is tried once in the browser at hand, driven or headless, where the host has one, since a browser reads what a fetch tool cannot (reading-pages.md "Which tool reads a page"). A check, a login or an error there too ends the reading of that site from this host, with no sign-in and no request dressed up as a browser's ([walls.md](/docs/browser/walls.md)); most large community boards and social platforms answered an automated reading that way (checked 2026-11). No site is checked before the first message, because the sites are met in the search: a wall is said where it is met. What follows depends on what the site is to the run.

- **One source among several** (a board in the candidate search, a page that might hold an image): the run does not stop. It takes walls.md's ways in their order, as far as one source is worth. A browser of the user's own, where the host drives one, reads the site (way 1). Else the same material where it is published elsewhere (way 3): for a board's talk, a search limited to the site, which gives titles and no counts, then outlets' articles on what communities are talking about, whose quoted figures are the outlet's; for an image, the next source in [images.md](images.md)'s order. Another machine and pages the user carries (ways 2 and 4) are not asked for. The card's `Talk` line, or the brief's `notes` with its checkpoint and delivery, says what was not reached and which way gave the material; a board that gave nothing leaves the card "outlets only".
- **The pick's own articles**, where fewer than two outlets that carry it can be read in full: the run stops and offers walls.md's ways in their order, each with what the brief would lack, and a go-ahead takes the first the host allows.

## Where people talk

Outlets' feeds read first brought stories no board was talking about, and they were the ones dropped later. Light stories (something funny or absurd) are few in any one week: a seven-day search over more than a thousand items kept four, and the window was widened to two or three weeks at the user's word. A season's own stories are thin in the market's domestic outlets some weeks and come from abroad; one still ahead is searched again when it is near.

## Page readers

Which tool reads what, and what a fetch tool returned or refused, is in reading-pages.md "Which tool reads a page". Several articles on one story differ in small facts (a count given as three in one outlet and four in another, a figure present in one outlet only): read them all and cross-check, as [sourcing.md](sourcing.md) says.

## A video

Of a batch of stories, about a third had a clip worth taking: an agency's footage and an outlet's edit with its captions and logo were not the story's own video, and for some stories a still read better than the moving cover. For frames, the watch page rather than the embed, the `video` element pinned over the page, the one reload on a stall, the advertisements and the served quality are in video-frames.md "A watch page in a headless browser", which is what [video-frames.example.mjs](../scripts/video-frames.example.mjs) does on its own; a clip of several minutes was captured with the pinned element and reloads at a raised rate (checked 2026-10), and the present setting, normal speed with one reload on a stall, is untried. A clip may carry, after the footage, a re-enactment made with generated imagery and labelled as such on screen: its frames are set aside as illustrations.
